# Strand 产品文档

本文档从产品角度介绍 Strand：它是什么、为谁做、遵守哪些原则、现在能做什么、数据放在哪里、有哪些限制和后续方向。实现细节见 [技术文档](技术文档.md)；每个功能的逐条交互规则见 [产品说明书](Strand%20产品说明书.md)；面向最终用户的操作指南见 [使用说明书](Strand%20使用说明书.md)。

对应版本：0.1.11（Strand 是暂定名）。

---

## 1. 产品定位

Strand 是一个跨平台的桌面 Git 客户端，支持 macOS 和 Windows。它的功能和布局照着 JetBrains IDE（IntelliJ IDEA、WebStorm 等）的 Git 集成来做：不用打开 IDE，也能用同样的方式提交、看历史、处理分支和解决冲突。界面有中文和英文两种语言。

和其他 Git 客户端相比，Strand 的特点是：

- **几乎每一步都能撤销**：⌘Z 能撤销提交、重置、变基、删除分支、丢弃改动、拣选等，重做还能再做回来。
- **大仓库不卡**：8.6 万提交的仓库约 135 毫秒打开，长连线会被折叠，提交图不会变得很宽。
- **行为和命令行一致**：提交、合并、网络操作都交给电脑上装的 Git 执行，钩子、签名、换行转换、凭据助手和配置都照常生效。
- **不需要额外配置**：认证用你已有的 SSH 密钥和凭据助手；代码导航靠文本搜索，不需要语言服务器。

### 1.1 目标用户

| 用户 | 主要诉求 |
| --- | --- |
| 习惯 JetBrains Git 界面的开发者 | 不打开 IDE 也能用同样的方式提交、看日志、解决冲突 |
| 使用其他编辑器的开发者 | 需要一个比命令行直观、比现有客户端轻的图形界面 |
| 处理大仓库的团队 | 十万级提交的仓库打开和滚动不卡；能稀疏检出只要的目录 |

### 1.2 设计原则

所有功能共同遵守这六条：

1. **每个写操作都能撤销。** 提交、合并、变基、重置、丢弃改动等都记入操作日志，可以一步退回。
2. **有风险的操作先说明影响。** 执行前告诉用户会改写几个提交、是否需要强制推送、改动会不会丢。
3. **操作用图标按钮。** 每个图标按钮都有悬停提示和无障碍标签。
4. **不可用的操作置灰，不隐藏。** 悬停提示里写明原因。
5. **提交面板和日志同屏。** 不在「改动」和「历史」之间切换页面。
6. **冲突按修改块处理。** 每个修改块都要明确接受或舍弃，才能完成合并。

此外：所有操作都能只用键盘完成，浅色和深色主题下文字对比度都不低于 4.5:1。

## 2. 界面概览

主窗口从左到右分为四块，宽度都能拖动：

| 区域 | 内容 |
| --- | --- |
| 左侧面板 | 「提交」（改动的文件、提交说明）、「暂存架」「贮藏」「文件」（项目文件树和全文搜索）四个标签页 |
| 分支树 | 当前分支、本地、远程、标签、工作目录、子模块，支持收藏和搜索 |
| 日志 | 过滤栏和提交图；下方是操作时间线 |
| 详情 / 标签页 | 选中提交的详情；文件、diff 以标签页形式打开 |

顶部工具栏：仓库和分支切换、命令面板（⌘K）、撤销/重做、抓取/拉取/推送（带领先落后角标）、语言、设置。

## 3. 功能全景

### 3.1 历史

- **提交图**：长连线折叠，大仓库也窄；按时间或图顺序排序，只看第一父提交、隐藏合并提交、折叠线性分支。
- **过滤**：按文字（正则、大小写）、分支、作者（多选或规则）、日期范围、路径过滤；在历史改动里搜索（`git log -S` / `-G`），提交详情只列出匹配的文件。
- **单个文件**：逐行追溯（blame），可以一路追到某一行改动之前的版本；跟随重命名的文件历史；任意两个版本对比，跨重命名也行。
- **工具**：二分查找（bisect，日志上方有进度条）、操作记录（reflog，找回丢失的提交）、贡献统计（每位作者和每月的提交数、改动行数，星期 × 小时的活跃热力图，点作者直接过滤日志）。

### 3.2 提交

- 按整个文件或单独几行提交；变更列表（像 JetBrains 一样把改动分组分别提交）；提交说明历史、`commit.template`、以他人身份提交、`Co-authored-by`。
- 提交前运行格式化和检查命令，问题按文件和行号列出。
- 修订（amend）、fixup、squash 到更早的提交；整理提交窗口（交互式变基：调整顺序、保留、并入、丢弃、改说明）。
- 暂存架（按文件、可命名、可部分恢复）和贮藏，都可以包含未跟踪文件；贮藏可以转成新分支。
- Git 钩子：列出仓库的钩子和用途、在编辑器里改、开关、试运行；钩子拦下提交时显示完整输出，并提供跳过钩子提交。

### 3.3 撤销

- 操作时间线记录每个写操作；⌘Z 撤销、⇧⌘Z 重做。
- 越过已推送提交的步骤先确认；被别处改过的步骤标记为不可撤销。
- 中止合并、变基、拉取本身也能撤销。

### 3.4 分支和远程

- 分支树：收藏、工作目录、标签、多个远程；把一个分支拖到另一个上即可合并或变基；合并方式包括 no-ff 和 squash。
- 抓取、拉取（合并或变基；预计有冲突时先给出摘要）、推送（预览、`--force-with-lease`、「推送到此处」、推送标签）。
- 清理已合并的分支（一步完成、可撤销）；抓取时修剪远程已删除的分支；删除远程分支和标签；设置上游。
- 远程管理：添加、改地址、重命名、删除。
- PR / MR：列出 GitHub 和 GitLab 上开放的 PR/MR 及其 CI 状态，检出分支，在浏览器里打开，从当前分支创建。
- 凭据弹窗：需要用户名、密码或 SSH 口令时弹出，回答只交给那一个 git 进程，不保存。

### 3.5 冲突

- 冲突列表和三栏合并窗口：逐个修改块标记，预览结果，撤销重做，可以稍后继续。
- 图片冲突可以并排、滑动对比、叠加查看。

### 3.6 diff 和文件

- 统一或并排 diff，未改动的部分折叠，连接色带、位置标尺、语法高亮、缩进参考线、面包屑。
- **彩虹括号**：`()`、`[]`、`{}` 按嵌套深度着色，XML/HTML/JSX 标签也按元素深度着色；代码里配不上的括号和 XML 里对不上的标签标红。所有文本文件都支持（识别 74 种语言，其他文件按纯文本处理）。
- 直接在 diff 或文件标签页里编辑（代码编辑器：语法颜色、查找替换、跳到行、撤销、自动保存）。
- 图片 diff、比较任意两个文件、和剪贴板比较；只拣选或还原一个提交里的部分文件；从任意版本取回文件；应用补丁（粘贴、选文件或拖到窗口上）。
- **文件预览**：图片、Markdown（所见即所得、源码、分栏，滚动同步，大纲）、CSV 表格、JSON 树、PDF、音视频、textconv 输出；可以安装预览插件支持新格式。
- **代码导航**：按住 ⌘ 点击跳到定义（跟着 import 走），⌥⌘B 列出所有同名定义，⌥F7 查找用法，⌘[ ⌘] 后退前进，⇧⌘O 按名字打开文件。

### 3.7 大仓库和维护

- 稀疏检出：勾选要放到磁盘上的文件夹；稀疏克隆超大仓库。
- Git LFS：diff 和文件视图显示真实内容，未下载的可以按需拉取。
- 子模块：显示状态、更新、在 Strand 里打开。
- 仓库维护：查看 `.git` 里什么占空间，`git gc` 清理（可中途停止），开启 rerere 记住冲突的解决方式。

### 3.8 应用体验

- 命令面板 ⌘K：搜索命令、分支和提交。
- IDE 风格的右下角通知气泡，带撤销、查看拉取到的提交等链接；通知记录可以在命令面板里打开。
- 文件标签页：固定、拖动排序、⇧⌘T 重新打开、⌘E 最近的文件。
- 多窗口；退出前询问未保存的修改；下次启动恢复所有窗口。
- 设置：语言、主题（跟随系统/浅色/深色）、**整体缩放**（80%–150%，⌘= / ⌘− / ⌘0）、彩虹括号、自动保存、自动抓取、Git 配置（用户名、邮箱、代理、换行、默认分支名，全局或按仓库）。
- 自定义快捷键：所有全局快捷键都能在设置里改，有冲突检查和恢复默认。
- 应用内更新：启动时检查 GitHub Releases，更新包签名校验。
- 控制台：按顺序列出 Strand 运行过的 git 命令和输出。

## 4. 数据与隐私

- Strand 自己的数据放在仓库的 `.git/strand/` 里：操作日志、暂存架、变更列表、收藏的分支等，不会进入版本控制。
- 设置和界面记忆存在应用本地。
- **不保存任何密码和令牌**。认证用你已有的 SSH 密钥、凭据助手和系统钥匙串；PR/MR 的令牌也交给 Git 的凭据助手保存。
- 控制台和日志文件里的密码、令牌会被替换成 `***`。
- 预览插件在沙箱里运行，不能联网。
- 除了检查更新（GitHub Releases）和你主动使用的 PR/MR 功能（GitHub/GitLab API），Strand 不访问网络服务；Git 自己的网络操作照常经过你配置的代理。

## 5. 平台和要求

| 平台 | 安装包 |
| --- | --- |
| macOS（Apple 芯片） | `.dmg` |
| Windows 10 / 11（x64） | 安装程序 `.exe`、`.msi`、免安装版 `.exe` |

- 需要电脑上装好 Git 2.30 或以上；试运行钩子需要 Git 2.36 以上；代码导航需要支持 PCRE 的 Git。
- macOS 包没有公证，第一次打开要右键选「打开」；Windows 包没有签名，SmartScreen 可能要求确认。

## 6. 限制

- 暂存架按整个文件处理。
- 撤销快照不包括未跟踪文件（未跟踪文件本身的操作除外）；强制删除的工作目录里的改动无法找回。
- 整理提交遇到合并提交就停。
- 克隆只用系统 Git，认证依赖 SSH 密钥和凭据助手。
- PR/MR 只能列出和创建，不能在 Strand 里审查、评论或合并；只识别主机名里带 github 或 gitlab 的托管平台。
- 提交前检查的设置存在每个仓库的 Git 配置里，不能通过仓库共享。
- 代码导航靠文本搜索：同名定义会全部列出，找不到仓库外依赖里的定义。
- 不支持 reftable 格式的仓库（打开时会提示）。
- Markdown 预览不加载网上的图片。

## 7. 范围和后续方向

**明确不做**：AI 生成提交说明或解释冲突；不经过 Git 的本地文件历史（误改误删靠撤销和 reflog 找回）；Intel Mac 和 Linux 构建、macOS 公证、自定义标题栏。

**可以考虑的方向**：

| 方向 | 说明 |
| --- | --- |
| 更多托管平台 | Gitea、Codeberg、Gitee 的 API 和 GitHub 接近，接入成本低；Bitbucket 差别较大 |
| 在应用里审 PR | 复用「比较」功能对比 PR 分支和目标分支；进一步支持评论、批准、合并 |
| 贡献统计改进 | 默认排除锁文件和生成文件；按路径过滤 |
| range-diff | 整理提交前后逐个对比；操作日志里已经有前后快照 |
| 只调代码字号 | 在整体缩放之外单独调编辑器和 diff 的字号 |

**待确认**：

- 产品名。
- 提交前检查要不要支持提交进仓库、全队共用的配置文件。
