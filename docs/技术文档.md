# Strand 技术文档

本文档写给要读懂、修改或发布 Strand 的开发者，讲系统怎么搭起来、数据怎么流动、各模块怎么实现，以及怎么测试和发布。产品功能见 [产品文档](产品文档.md)，逐条交互规则见 [产品说明书](Strand%20产品说明书.md)（代码注释里的 `spec §x` 指它的章节）。

对应版本：0.1.11。

---

## 1. 总体架构

Strand 是 Tauri 2 桌面应用，分三层，依赖只朝一个方向：

```
┌──────────────────────────────────────────────────────────────┐
│ 前端  src/  (React 19 + TypeScript + Vite + CodeMirror 6)      │
│   只负责显示和交互；不自己推断 Git 状态                        │
│   唯一入口：src/api/commands.ts（invoke 的类型化封装）          │
└───────────────▲──────────────────────────────┬───────────────┘
                │ 事件 repo_changed / 控制台 / 进度 │ invoke(命令名, 参数)
┌───────────────┴──────────────────────────────▼───────────────┐
│ 外壳  src-tauri/  (Tauri 2)                                    │
│   170 个 #[tauri::command] 薄封装；窗口、菜单、权限、插件、      │
│   文件监听、askpass 服务、自动更新、strand-plugin:// 协议       │
└───────────────▲──────────────────────────────┬───────────────┘
                │ Rust 函数调用                  │
┌───────────────┴──────────────────────────────▼───────────────┐
│ 核心层  crates/strand-core/  (不依赖 Tauri，可单独测试)         │
│   Git 读写、提交图布局、操作日志/撤销、冲突、远程、错误码、数据模型 │
└──────────────────────────────────────────────────────────────┘
```

**分工原则（spec §2）**：所有 Git 状态都在核心层计算好再返回，比如提交能不能撤销、按钮为什么置灰、冲突两边各叫什么。前端只按返回的数据显示，不重复判断。

### 1.1 Git 访问的三种方式

| 方式 | 用在哪里 | 为什么 |
| --- | --- | --- |
| **gix**（纯 Rust） | 读日志、遍历提交、refs | 快：86k 提交的仓库约 135 ms 打开（有 commit-graph 时） |
| **git2**（libgit2） | 工作区状态、diff、分支列表、blame 之外的读操作 | API 完整，diff 和 status 方便 |
| **系统 git**（子进程） | 提交、合并、变基、所有网络操作、stash、钩子相关 | 钩子、签名、换行转换、凭据助手、配置都和命令行完全一致 |

系统 git 统一经 `git_cli::run` / `run_env` 调用：设 `GIT_TERMINAL_PROMPT=0`、`GIT_EDITOR=true`，不弹编辑器和终端提示；Windows 上隐藏控制台窗口；失败时返回 `GIT_FAILED`，`detail` 带 args、stderr、stdout。要求 Git 2.30 以上，启动时 `git_check` 检测。

### 1.2 技术选型

| 部分 | 选择 |
| --- | --- |
| 桌面框架 | Tauri 2（插件：opener、dialog、window-state、notification、updater） |
| 核心语言 | Rust 2024 edition，workspace：`src-tauri`、`crates/strand-core` |
| 前端 | React 19、TypeScript 6、Vite 8、CodeMirror 6、highlight.js 11、marked + DOMPurify |
| 其他 Rust 依赖 | notify（文件监听）、similar（行级 diff）、regex、trash（废纸篓）、ureq（GitHub/GitLab API）、tempfile |

## 3. 前后端通信

### 3.1 命令

- 每个功能在核心层实现并测试，在 `src-tauri/src/lib.rs` 包一层 `#[tauri::command]`，注册进 `generate_handler!`，再在 `src/api/commands.ts` 加类型化函数、在 `src/api/types.ts` 加类型。数据模型改动要同时改 `model.rs` 和 `types.ts`。
- 读操作都放到后台线程（`spawn_blocking`），不阻塞界面线程（spec §15）。
- 仓库会话 `Session` 放在 `AppState.repo: Mutex<Option<Session>>` 里；`with_repo` 取锁执行。网络操作、路径过滤、贡献统计等慢操作**不持有 Session**，只用仓库路径，跑的时候界面照样能看日志和 diff。
- 写操作经 `logged_op*` 包装：执行前后各拍快照写入操作日志，返回 `{ result, state, op? }`。`op` 是写进日志的那一条，界面用它显示「撤销」。

### 3.2 错误

所有失败都返回统一结构（spec §14，`error.rs`）：

```json
{ "code": "PUSH_REJECTED", "message": "可以直接给用户看的中文说明", "detail": { ... } }
```

`code` 是固定枚举，前端据此决定怎么展示：`REPO_BUSY` `MERGE_IN_PROGRESS` `NOTHING_SELECTED` `EMPTY_MESSAGE` `ALREADY_PUSHED` `INVALID_NAME` `INVALID_RANGE` `WORKTREE_CONFLICT` `CONFLICTS` `UNMARKED_BLOCKS` `CONFLICT_MARKERS` `PUSH_REJECTED` `AUTH_FAILED` `NETWORK` `STATE_DIVERGED` `NOT_FOUND` `CANCELLED` `GIT_FAILED` `HOOK_FAILED` `NOT_A_REPO` `NO_REPO` `GIT_MISSING` `INVALID_REGEX` `PARTIAL_CLONE`。核心层的 `message` 是中文，英文界面显示时由 `tr()` 查 `en.ts` 翻译（整句或带 `{0}` 的模板）。

### 3.3 事件

| 事件 | 来源 | 用途 |
| --- | --- | --- |
| `repo_changed { scopes }` | 文件监听（第 5.4 节） | 外部改了仓库，按范围刷新 |
| 控制台条目 | `console::set_sink` | 控制台实时显示 git 命令 |
| 网络进度 | fetch/pull/push | 工具栏进度和取消 |

### 3.4 浏览器预览模式

`commands.ts` 检查 `__TAURI_INTERNALS__`：不在 Tauri 里（`pnpm dev`）时，每个命令自动改用 `mock.ts` 的假数据。只改界面时不用编译 Rust。

## 5. 关键机制

### 5.1 日志加载

1. `Session::open` 用 gix 发现仓库，`reload` 收集所有 refs，从 HEAD 和各分支尖端遍历提交（HEAD 排最前，同一时间的提交当前分支优先；refs 排序后再遍历，保证结果稳定）。有 commit-graph 文件时走快速路径。
2. `graph` 计算泳道和线段，长边折叠。
3. 前端 `useLog` 按需分页请求（`log_query(filter, sort, offset, limit)`），已加载的页缓存。过滤结果不完整时（`partial`）每 300 ms 重新请求已加载的页，旧行保留到新结果到达，避免闪烁。
4. 文件监听报告 refs 变化时调用 `repo_refresh`：`reload_if_changed` 先比较 refs 和 HEAD，没变就不重读日志（Strand 自己写操作后已经读过）。

### 5.2 操作日志、撤销和重做（spec §11）

- 每个写操作执行前后各拍一张快照：HEAD、本地分支和标签的位置、索引的树、已跟踪工作区文件的树。快照树写进 Git 对象库，每条日志在 `refs/strand/ops/<id>` 留一个提交（树里放四棵快照树，父提交是前后两个提交），所以撤销掉的提交和删除的分支不会被 gc 回收。
- 日志存在 `.git/strand/oplog.json`，保留最近 200 条、30 天。重做列表只在内存里。
- 撤销 = 恢复 `before`，重做 = 恢复 `after`。恢复前检查：HEAD 和这一步改过的 refs 必须还在它留下的位置，否则返回 `STATE_DIVERGED`；文件按路径检查，只动这一步改过的文件，其他文件的后续修改保留。
- 越过已推送提交的步骤先确认；推送只显示在时间线上，不能撤销。`tests/undo_all.rs` 对每种操作做一遍「操作 → 撤销 → 核对」。

### 5.3 提交

- 整文件提交直接调用 `git commit`，钩子、签名照常运行。
- 部分行提交：在临时索引里按 HEAD 搭好要提交的内容（逐字节拼接，保留换行符和末尾有没有换行），用 `GIT_INDEX_FILE` 运行 `git commit`，再把真正索引里这些路径对齐到新 HEAD。
- 钩子拦下提交时返回 `HOOK_FAILED`，`detail` 带钩子名和完整输出。

### 5.4 文件监听和自动刷新（`watch.rs`）

- notify 递归监听工作区，100 ms 防抖（spec §15 要求文件改动 300 ms 内显示）。
- 分类：`.git` 里的 `HEAD`/`refs/*`/`packed-refs`/`MERGE_HEAD`/`rebase-*` → `Refs`；`index` 或工作区文件 → `Status`；`refs/stash` → `Stash`；`strand/shelf/` → `Shelf`。跳过 `.lock`、`refs/strand/`、`ORIG_HEAD` 和 `.gitignore` 忽略的文件。
- 链接的工作目录（`git worktree add`）的 git 数据在文件夹外面：自己的 git 目录（HEAD、index、暂存架）和共用 git 目录（分支、标签、贮藏）都另外监听；共用目录只看 refs，不看主工作目录的 HEAD 和 index。
- 前端 `App.tsx` 收到 `refs` 刷新日志、分支和状态；`status` 刷新提交面板和当前 diff，并刷新时间线（被外部改过的步骤要显示为不可撤销）；`stash`/`shelf` 只刷新对应列表。

### 5.5 远程操作和凭据

- fetch、pull、push 都调用系统 git，认证交给用户已有的 SSH 密钥、凭据助手和钥匙串。
- 需要输入用户名、密码或 SSH 口令时，git 运行 `GIT_ASKPASS`/`SSH_ASKPASS` 指向的程序。这个程序就是 Strand 自己：以 askpass 模式启动时（环境变量里有端口和一次性 token），它连回发起网络操作的进程，把提示交给界面弹窗，再把回答打印给 git。回答只交给那一个 git 进程，不保存。
- PR/MR 的令牌通过 `git credential fill` 从用户的凭据助手读取；用户手动输入的令牌交给 `git credential approve`，由同一个凭据助手保存。Strand 自己不存令牌。
- 控制台和日志文件会脱敏：URL 里的密码、`Authorization:` 和 `password=` 后面的内容替换成 `***`。

### 5.6 冲突解决（spec §8）

核心层读出冲突文件，按 base / 你的 / 对方的三个版本切成上下文和修改块，并把 Git 变基时反直觉的 ours/theirs 转换成用户视角的名字。标记状态（接受哪边、撤销重做、稍后继续）由前端保存；应用一个文件时前端一次传入该文件的全部标记，核心层生成结果并写回。

### 5.7 语法高亮和彩虹括号

- **查看器**（文件视图、diff、blame、冲突窗口）：`src/highlight/hl.worker.ts` 在 Web Worker 里用 highlight.js 着色整段文本，再拆成每行的 `[start, end, kind]`。识别 74 种语言（`index.ts` 的扩展名和文件名表），不认识的文件按纯文本处理。超过 1 MB 或 2 万行不着色。
- **彩虹括号**：`()`、`[]`、`{}` 按深度用 4 种颜色循环，字符串和注释里的括号不算。代码语言里不配对的括号标红（`br-bad`）；Markdown、HTML/XML、Shell、YAML、INI、纯文本等是宽松语言，不标红（`brackets.ts` 的 `LENIENT`）。只有完整文件才标红，diff 片段不标。
- **标签彩虹**：XML、HTML、JSX 的标签按元素深度着色，类名 `tag-br0..3`。XML 里对不上的标签标红；HTML 认识 void 元素（`<br>` 等）、隐式结束（`<li>`、`<p>`、`<td>` 等）和大小写不敏感，不标红。
- **编辑器**：`src/components/rainbow.ts` 是 CodeMirror 插件，括号按语法树跳过字符串和注释，标签按 `Element`/`JSXElement` 层数着色，规则和查看器一致。超过 20 万字符的文件不上色。
- 关闭彩虹括号只是在根元素加 `data-rainbow="off"`，CSS 恢复颜色，不重新计算。

### 5.8 设置、快捷键和缩放

- 设置存在 `localStorage` 的 `strand.settings`（`settings.ts`），改动通知订阅者；其他窗口通过 `storage` 事件同步。快捷键覆盖存在 `strand.keys`（`keymap.ts`），组合键写成 `Mod+Shift+T`，Mod 在 macOS 是 ⌘。
- 整体缩放（`zoom.ts`）：Tauri 里调用 webview 的 `setZoom`，所有尺寸一起缩放，日志、diff、冲突窗口写死的行高也不会错位；浏览器预览里用 CSS `zoom` 代替。需要权限 `core:webview:allow-set-webview-zoom`。
- 其他浏览器存储键：`strand.lang`、`strand.repos`、`strand.lastRepo`、`strand.statsRange`、`strand.mergeMode`、`strand.mergeView`、`strand.cloneDir`、`strand.skipUpdate`、`strand.treeOpen`、`strand.panelOpen` 等。

### 5.9 多窗口

每个窗口是独立进程（`open_new_window`）。`windows.rs` 让每个窗口在应用数据文件夹写 `windows/<pid>.json`（路径、最近活跃时间、是否聚焦）并定期刷新；下次启动时，「最近活跃时间」过期的文件就是上次留下的窗口，逐个恢复。设置「启动时打开」决定启动行为：`windows` 恢复这些窗口，`last` 只打开 `strand.lastRepo` 记的仓库，`welcome` 显示欢迎页；`session_restore` 在后两种情况下也会调用（传 `false`），只清理过期记录、不拉起窗口。0.1.11 之前的布尔设置 `reopenLast` 在读取设置时自动迁移。⌘Q 退出前先询问未保存的修改。调试版用单独的窗口记录，测试运行不会打开已安装应用的窗口。

### 5.10 预览插件

插件放在应用数据文件夹的 `plugins/<id>/`，`manifest.json` 声明支持的扩展名和入口页面。页面通过 `strand-plugin://localhost/<id>/<file>`（Windows 上是 `http://strand-plugin.localhost/...`）提供，只能读插件自己文件夹里的文件（规范化路径后检查），每个页面带不允许联网的 CSP，在沙箱 iframe 里运行，只拿到要预览的文件内容。见 [预览插件](Preview%20Plugins.md)。

### 5.11 代码导航

`symbols.ts` 和 `nav.ts` 用 `git grep` 加 import 解析找定义和用法，不需要语言服务器：定义是名字跟在定义关键字（fn、function、def、class、struct…）后面的行；同文件优先，再找同语言的文件；TS/JS、Python、Rust 会跟着 import 走。需要支持 PCRE 的 Git（`git grep -P`）。

### 5.12 自动更新

启动时（可在设置里关掉）读取 `https://github.com/calabli/Strand/releases/latest/download/latest.json`。更新包用 updater 私钥签名，公钥在 `tauri.conf.json` 的 `plugins.updater.pubkey`；签名对不上的包不会安装。调试版可以用 `STRAND_UPDATE_ENDPOINT` 指向本地的 `latest.json`。

## 6. 数据存放位置

| 位置 | 内容 |
| --- | --- |
| 仓库 `.git/strand/oplog.json` + `refs/strand/ops/*` | 操作日志和快照 |
| `.git/strand/shelf/` | 暂存架补丁和列表（删除 30 天后才真正清理） |
| `.git/strand/changelists.json` | 变更列表（每个工作目录一份） |
| `<共用的 .git>/strand/favorites` | 收藏的分支（工作目录之间共用） |
| `.git/strand/` 其他文件 | 冲突记录、远程标签记录、拉取时的临时暂存架等 |
| 仓库 `.git/config` | 提交前检查的命令、rerere 开关等仓库级设置 |
| 应用数据文件夹 | `plugins/`、`windows/<pid>.json`、本地日志文件 |
| WebView 的 localStorage | 设置、快捷键、最近的仓库、各种界面记忆（第 5.8 节） |

Strand 写在 `.git` 里的东西都不会进入版本控制。贡献统计等查询结果不落盘，每次现场计算。

---

## 7. 安全边界

- **写工作区文件**（编辑器保存、恢复或删除文件、粘贴图片、单行回滚）：路径必须是相对路径、不含 `..`、不在 `.git` 里（`check_rel_path`）；写入前还要把所在文件夹的符号链接解析掉，确认仍在仓库里（`inside_worktree`），防止仓库里提交的符号链接把写入引到外面。
- **凭据**：不保存任何密码和令牌；askpass 回答只给发起的 git 进程；日志脱敏。
- **插件**：路径限制在插件文件夹，CSP 禁止联网，沙箱运行。
- **Markdown 预览**：marked 渲染后用 DOMPurify 清理，网上的图片不加载。
- **主窗口 CSP**：见 `tauri.conf.json` 的 `app.security.csp`。

## 8. 性能

规格第 15 节的目标已经实测。测量方法：

```bash
mkdir /tmp/perf && cd /tmp/perf && git init -q -b main . \
  && python3 <项目路径>/scripts/gen_perf_repo.py 10000 5000 | git fast-import --quiet \
  && git checkout -q -f main && git config user.name test && git config user.email t@example.com
cargo run --release -p strand-core --example perf -- /tmp/perf
```

`perf` 会改工作区和分支，只能用临时仓库。其他工具：`--example log`（打开和读日志）、`--example log_stream`（过滤结果分批返回）、`--example blame`。

开发构建里依赖包和 `strand-core` 也开 `opt-level = 2`（`Cargo.toml`），否则 gix 遍历和图布局在调试版里慢十倍，测出来的时间没有意义。

## 9. 开发

```bash
pnpm install
pnpm dev            # 只跑前端，用假数据（浏览器打开 http://localhost:1420）
pnpm tauri dev      # 完整桌面应用
pnpm typecheck      # TypeScript 检查
cargo test --workspace                       # 全部 Rust 测试
cargo clippy --workspace --all-targets       # 应保持零警告
```

`.claude/launch.json` 里有 `web`（前端）、`tauri`（桌面应用）、`site`（官网）三个启动配置。

### 9.1 约定

- **新增命令**：核心层实现并加测试 → `lib.rs` 薄封装并注册 → `types.ts` 和 `commands.ts`（必要时 `mock.ts`）。
- **界面文字**：写成 `t("中文原文")`，在 `src/i18n/en.ts` 加英文。核心层返回的中文消息也要在 `en.ts` 里有翻译。
- **注释**：代码注释用英文；`spec §x` 指产品说明书的章节。
- **Rust 格式**：项目没有用 rustfmt（行宽超过默认值），改动时保持周围的写法；let-chain 的 `{` 单独一行。
- **测试**：核心层的行为测试放在 `crates/strand-core/tests/`，用临时仓库跑真实 git（`GIT_CONFIG_GLOBAL=/dev/null`，不受本机配置影响）；纯函数的单元测试放在模块末尾的 `mod tests`。

### 9.2 持续集成（`.github/workflows/build.yml`）

| Job | 运行环境 | 内容 |
| --- | --- | --- |
| Test (core + typecheck) | macOS | `cargo test --workspace`、`pnpm typecheck` |
| Build | macOS arm64、Windows x64 | `tauri build`，收集 dmg、app.tar.gz、setup.exe、msi、免安装 exe |
| Release | Ubuntu，仅 `v*` tag | 用上一个 tag 以来的提交标题生成更新说明（跳过发版和官网提交），生成 `latest.json`，创建 GitHub Release |

`pages.yml` 在 `site/` 变化时部署官网。

### 9.3 发布流程

1. 把 `Cargo.toml`、`package.json`、`src-tauri/tauri.conf.json` 的版本号改成一致；`cargo update -p strand -p strand-core` 更新 `Cargo.lock`；改 README 的「当前版本」和使用说明书里的版本号、安装包文件名。提交为 `Release x.y.z`。
2. 打带注释的 tag 并推送：`git tag -a vx.y.z -m "Strand x.y.z" && git push origin main vx.y.z`。
3. CI 成功后，把 `site/index.html` 的下载链接和文件大小改成新版本，提交为 `Website: download links for x.y.z` 并推送。

更新包签名需要仓库 secret `TAURI_SIGNING_PRIVATE_KEY`（没有密码）。没有它构建也会成功，但不带更新包，已安装的版本收不到更新。私钥丢失后，新密钥签的版本无法更新带旧公钥的安装。

## 10. 已知的技术限制

- 不支持 reftable 格式的仓库（gix 和 libgit2 都读不了），打开时会明确提示。
- 编辑器的彩虹括号每次输入都重扫整个文档，20 万字符以上不上色。
- 撤销快照不包括未跟踪文件（未跟踪文件本身的操作除外）；强制删除的工作目录里的改动无法找回。
- 变基窗口遇到合并提交就停。
- macOS 包只做了临时签名、没有公证；Windows 包没有签名；不构建 Intel Mac 和 Linux。
